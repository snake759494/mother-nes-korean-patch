# 기술 문서

## ROM
- 원본: MMC3(매퍼 4) PRG 256KB + CHR 128KB. 패치 후 PRG 512KB, 매퍼 191(NES 2.0, CHR-RAM 2KB 추가)로 바꿉니다.
- 원래 고정 뱅크(0x1E/0x1F)는 512KB 끝(0x3E/0x3F)으로 복사합니다.
- 추가한 뱅크: 0x20 = 한글 처리 코드(`$A000`에 매핑), 0x21~ = 글리프 데이터(글자당 8바이트, 1bpp).

## 글자 부호
- 원래 1바이트 문자 가운데 쓰지 않는 155개 부호를 자주 쓰는 한글(K1)에 배정합니다.
- 나머지 한글은 2바이트: `$38-$3F` + `$40-$FF`(192×8).
- 조사: `3F F8+n` 토큰. 직전 글자의 받침(`LASTB`)을 보고 은/는, 이/가, 을/를, 과/와, 아/야, (으)로, (이)랑을 고릅니다. 이름처럼 실행 중에 바뀌는 글자 뒤에서도 맞는 조사가 나옵니다.

## 글자 캐시
- 화면에 그릴 때 글리프를 CHR-RAM의 108개 빈 타일 슬롯에 올립니다. 교체는 LRU(마지막 사용 시각 `$0130-$019B`).
- 슬롯별 글리프 번호 표(`IDLO`/`IDHI`)는 SRAM의 텍스트 복사 영역 안 빈자리에 두고, `MAGIC`이 `$A5`가 아니면 처음 쓸 때 초기화합니다. SRAM 쓰기 전후로 `$A001`에 `$80`/`$C0`을 써서 잠금을 풉니다.
- 업로드는 NMI에서 큐(`$0101-$0125`)로 처리합니다. `$0600-$06FF`는 상태 화면에서 게임이 쓰므로 피합니다.

## 텍스트 배치
- 본편 대사: 원래 자리에 넣고, 넘치면 줄 단위로 끊어 같은 뱅크의 빈 공간으로 `GOTO`(04)합니다.
- 전투 메시지: 포인터 표(`0x780-0x8D2`)를 고쳐 뱅크 0에 다시 채웁니다.
- 아이템·PSI·상태 이름(포인터 `0x1800+8k`, `0x3C809`), 적 이름(`0x2C000+32n+0x18`)도 다시 채웁니다.
- 숫자 문자열 경로는 `($64)`에서 읽으므로 `PSEL`로 포인터를 고릅니다(`$FF0A` 훅).
- 고정 폭 템플릿·메뉴·이름 입력 표는 K1 글자로 같은 폭에 맞춥니다(`tmpl.py`).

## 검증
- `vfy.py`: ROM의 대사 904개를 GOTO를 따라 읽어 번역문 인코딩과 대조.
- Mesen Lua 하네스로 대사 894개를 실제 대사 창에 차례로 띄우고, 화면 네임테이블과 CHR-RAM을 읽어 글리프와 대조해 깨진 글자가 없는 것을 확인했습니다.
